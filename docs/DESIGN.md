# How gantt-a11y works, in detail

The README's "How it works" in full: each decision with the dates and the VoiceOver findings behind it. Moved here from the README on 2026-11-19 without changes. The specification's own record of decisions is in [ANNOUNCEMENTS.md](ANNOUNCEMENTS.md), "Implementation notes".

- Only the public, typed API of dhtmlx-gantt 10.0.3 is used: no private objects.
- Answers to commands go to a visually hidden `aria-live="polite"` region, one per gantt instance, with `lang` set to the strings' locale. Each announcement is a new node, so pressing a key again repeats it.
- When a command moves focus to another row (jumps, the next conflict, back) or focus comes back to the row from the task form, the screen reader reads that row's label first, and a live region would always be heard after it. In these cases the result is put in front of the row label for that moment: a wrapper around the public template `gantt.templates.tooltip_text` returns the result followed by the row's own label, for that task only. It is removed, and the row re-rendered, when focus leaves the row (to another element, to nothing, or to another window) and at the latest 5 seconds after focus landed; a result is never spoken twice. If focus does not land within 600 ms, the result goes to the live region; if focus could not move at all, it is dropped. A wrapper keeps the template it replaced in its own closure, so an application that wraps the template in turn neither breaks it nor is broken by it.
- **With the tooltip plugin** (`gantt.ext.tooltips`), which shows the same template to sighted users on hover, the template is never wrapped: these results go to the live region and are heard after the row. The same in cell navigation mode, where a cell's name does not come from this template.
- **What is announced is what was stored.** After a keyboard edit, a new link or a removed link, the extension reads the data again and speaks that; if the library or the application refused the change (`onBeforeTaskUpdate`, `onBeforeLinkAdd`, `onBeforeLinkDelete`), it says "Not changed. The change was not accepted.", "Link not created." or "Link not removed.". The stored task is not changed before the library allows it. The task form's result is built again from the stored task when the form closes.
- Keyboard edits (Shift+J, K, I, M) keep focus on the same row. The library re-renders the row and focuses it again, but VoiceOver in Safari did not announce that "change" of focus to the row it was already on (2026-11-18), so a result in the row label was not heard. Their results therefore go to the live region, after the re-render, and the row keeps its own label (with the new dates): the result is not read twice. A live region update right after the re-render was not heard either, so edit results wait 500 ms; a new press within that time replaces the waiting message. Confirmed by ear with VoiceOver in Safari on macOS 26.2 (2026-11-18). The same applies to Shift+C when the next conflict is on the focused task. For the task form the result is put into the row label when Save or Cancel is pressed, before the library re-renders the row and moves focus to it, so the focused row already carries it; re-rendering the row after focus had landed made VoiceOver silent. Confirmed by ear with VoiceOver in Safari on macOS 26.2 (2026-11-18).
- Gantt combines the results of event handlers with `&&`, so a handler that returns nothing would cancel actions such as saving the form; all handlers of this extension return `true`.
- The code has two parts: an engine in `src/core/` that knows nothing about dhtmlx or the DOM (texts, order, pages, conflicts, overlaps, bursts, help, levels), and adapters in `src/adapters/` (`dhtmlx/`, `frappe/`, and the shared live region in `dom/`) that read the chart, bind keys, listen to events, move focus and speak. [ADAPTERS.md](ADAPTERS.md) describes what an adapter for another Gantt library has to provide.
- Texts are built by pure functions in `src/core/text/`, covered by unit tests (`npm test`); the engine is also tested with an in-memory adapter (`test/memory-adapter.js`).
