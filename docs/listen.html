Listen: gantt-a11y announcement variants

Each Play button puts the text beside it into an ARIA live region, the same way the extension does. Turn on a screen reader, press a button, and compare what you hear. The texts and the letters match ANNOUNCEMENTS.md.

This page has no connection to the Gantt library and loads nothing from the network. Times are estimates at 170 words per minute, not measurements. To stop speech, use your screen reader's own key (Control in VoiceOver, NVDA and JAWS).

Variants of the main announcements

Section 4 of the specification. The chosen variant is marked "chosen".

Task row label

Focus lands on the task Testing: an ordinary task, 13 to 17 June 2026, 5 days, 40% complete. This text is the row's accessible name (the library builds it from gantt.templates.tooltip_text), not a live-region message.

  • Testing. Start date: 13 June 2026. End date: 17 June 2026.

    about 7 s. First: Name, then every value behind its full field label (today's demo template). Suits: Newcomers: each value is labelled with the same words as the form. Risk: Longest. The year and the words "date" repeat on every row; no duration or progress.

  • chosen

    Testing. 13 to 17 June, 5 days. 40 percent done.

    about 5 s. First: Name, then the time span as one phrase, then duration, then progress. Suits: Regular users who move through many rows. Risk: "13 to 17 June" has no field label; relies on the range reading as start and end.

  • Testing. Start 13 June. End 17 June. 5 days. 40 percent done.

    about 6 s. First: Name, then short labelled fields, one sentence per field. Suits: Newcomers and braille readers: one field per sentence, each with a label. Risk: Five sentence pauses per row make fast row-by-row scanning slower.

Dependencies on demand (Shift+D)

Focus is on Implementation. It depends on Software design (finish to start). Three tasks depend on it: Testing (finish to start), Documentation (start to start), Code review (finish to finish).

  • Depends on: Software design (finish to start). Required by: Testing (finish to start), Documentation (start to start), Code review (finish to finish).

    about 9.5 s. First: Direction, then every name with its link type in brackets (today's text). Suits: Users trained in project management who want every link type every time. Risk: Longest. Brackets are not spoken reliably, so a type can attach to the wrong name; the default type is repeated.

  • chosen

    Depends on: Software design. Required by 3. Testing. Documentation, start to start. Code review, finish to finish.

    about 8.5 s. First: Direction and count, then names; a link type only when it is not the default finish to start. Suits: Regular users; anyone listening for one specific name. Risk: Silence about the type has to be learned as meaning finish to start. "Start to start" is still jargon.

  • Starts after Software design ends. 3 tasks wait for this. Testing starts after this ends. Documentation starts after this starts. Code review ends after this ends.

    about 11 s. First: The scheduling rule itself in plain words, one sentence per link. Suits: Newcomers and people without project-management training. Risk: Longest to hear in full. "Starts after it starts" is exact but easy to mishear at speed.

Result of saving the task form

The user changed the duration of Testing from 5 to 8 days and pressed Save. The form closes and focus returns to the row. Today the result is spoken in place of the row label; on the fallback route it follows the row label.

  • Saved Testing. Duration: 5 days to 8 days. Ends 20 June 2026.

    about 6.5 s. First: Confirmation with the task name, then old value to new value (today's text). Suits: Newcomers who want the full sentence. Risk: "5 days to 8 days" sounds like a range. The name is spoken twice whenever the row label is also read.

  • chosen

    Saved. Duration 8 days, was 5. Ends 20 June.

    about 4.5 s. First: Confirmation word, then the new value, then the old one. Suits: Everyone; the first word already answers "did it work". Risk: No task name: when the result replaces the row label, nothing identifies the task.

  • Saved, 1 change: duration.

    about 2 s. First: Confirmation and which field changed; values are left to the row label, which must follow. Suits: Experienced users; braille readers (fits a 40-cell line). Risk: The user must read the row to get the new value; a wrong value typed by mistake is not echoed.

Link conflict after a change

Testing depends on Implementation (finish to start). Implementation ends 12 June. The user moved Testing two days earlier, to 11 June.

  • Warning: Testing now starts before Implementation ends.

    about 3 s. First: A warning word, then both task names and the broken rule (today's text). Suits: Newcomers: a full sentence with both names. Risk: Does not say by how much. "Warning" doubles with the "Alert" prefix some screen readers add to alerts.

  • chosen

    Conflict. 2 days too early for Implementation.

    about 3.5 s. First: Category word, then the size of the problem, then the other task. Suits: Everyone; tells how many key presses fix it, and is short enough to follow a move result. Risk: Does not say which rule is broken (start or end); "too early" leaves the subject implicit.

  • Conflict. 2 days too early: must not start before Implementation ends.

    about 5 s. First: Category word, size, then the rule in plain words with the other task. Suits: Newcomers; anyone who asks for the conflict on demand. Risk: Too long to append to a move result without passing 8 seconds.

  • Conflict with Implementation. Earliest start 13 June.

    about 3.5 s. First: Category word, the other task, then the date that fixes it. Suits: Users who think in dates and go straight to the fix. Risk: Hides the rule and the size; "earliest start" becomes "earliest end" for two of the four link types.

Tasks at the same time (Shift+O)

Focus is on Testing, 13 to 17 June. Marketing prep & PR runs 10 to 18 June; Documentation runs 5 to 14 June.

  • 2 tasks at the same time: Documentation, Marketing prep & PR.

    about 4.5 s. First: Count, then names in start order (today's text). Suits: Quick check of who else is active. Risk: Says nothing about how much they overlap; a one-day and a full overlap sound the same.

  • chosen

    2 tasks at the same time. Marketing prep & PR, the whole time. Documentation, first 2 days.

    about 7.5 s. First: Count, then names with the extent of overlap, largest overlap first. Suits: Everyone; answers "how much" without date arithmetic. Risk: "First 2 days" is relative to the focused task, which has to be understood once.

  • 2 tasks at the same time. Documentation, 5 to 14 June. Marketing prep & PR, 10 to 18 June.

    about 8.5 s. First: Count, then names with their own dates. Suits: Users who want raw dates and will compare them themselves. Risk: The listener has to compute the overlap in their head while the next item is already being spoken.

Moving a task with the keyboard (Alt+Shift+Right)

The user moves Testing one day later: from 13 to 17 June to 14 to 18 June.

  • Testing moved to 14 June 2026, ends 18 June 2026.

    about 5.5 s. First: Task name, the verb, then start and end with the year (today's text). Suits: Newcomers; a complete sentence. Risk: Name and year repeat on every key press; four words pass before the first new fact.

  • chosen

    Starts Sunday 14 June, ends Thursday 18 June.

    about 3.5 s. First: The new start with its weekday, then the new end. Suits: Everyone; the weekday exposes a move onto a weekend. Risk: Does not say how far the task moved.

  • 1 day later. 14 to 18 June.

    about 3.5 s. First: The size and direction of the move, then the new span. Suits: Experienced users; the shortest form. Risk: No weekday; "14 to 18 June" unlabelled.

Go to predecessor (Shift+P) when there are several

Launch depends on five tasks. The user presses Shift+P a second time; focus moves to the second of them and the screen reader reads that row.

  • Predecessor 2 of 5, finish to start.

    about 3 s. First: The relation as a noun, position, then link type (today's text). Suits: Users who know the term predecessor. Risk: Does not say whose predecessor; after a few jumps the starting task is forgotten.

  • chosen

    2 of 5. Launch depends on this.

    about 3.5 s. First: Position, then the relation as a sentence that names the task the user started from. Suits: Everyone; no jargon, and the origin is restated. Risk: The link type is left out unless it is unusual.

  • Predecessor 2 of 5 of Launch.

    about 2.5 s. First: The relation as a noun, position, then the origin. Suits: Users who chose project-management wording. Risk: "Of 5 of Launch" is awkward to hear.

Moving the task from the row itself

Put focus on the Testing row above (Tab to the grid, Up and Down arrows move between the two rows) and press Alt+Shift+Right or Left, once and then many times quickly. Each press redraws the row and focuses it again, as the library does, with the result as the row's label. Listen for whether each new result cuts off the one before it. The label goes back to normal when focus leaves the row.
